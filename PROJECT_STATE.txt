TalebElm Project Status Report
================================

Last updated: project foundation stage

WHAT HAS BEEN BUILT SO FAR
---------------------------

1. Five empty projects
The repository contains five project folders. They are all empty build
templates. They have names that match a Clean Architecture layout:

   - TalebElm.Domain        (src/TalebElm.Domain)
   - TalebElm.Application   (src/TalebElm.Application)
   - TalebElm.Infrastructure (src/TalebElm.Infrastructure)
   - TalebElm.Api           (src/TalebElm.Api)
   - TalebElm.Tests         (tests/TalebElm.Tests)

2. A solution file
   A solution file named TalebElm.slnx connects all five projects together,
   so they can be built and run as one group.

3. Project references
   The projects are linked in one direction (inward). Each project knows
   only about the project inside it:

   - Application can use Domain.
   - Infrastructure can use Application (and Domain).
   - Api can use Infrastructure (and, through it, Application and Domain).
   - Tests can use the other projects.
   - Domain does not use anything.

4. Documentation files
   Three guide files exist in the root folder:

   - README.md: introduces the project and explains how to install and run it.
   - CONTRIBUTING.md: a beginner-friendly guide to contributing the git steps.
   - ARCHITECTURE.md: explains Clean Architecture and what each layer is for.
   - AVAILABLE_TASKS.md: a list of small beginner tasks to start contributing.

5. Internal folder structures
   Each project has empty folders that show where future code will live:

   - Domain: Entities, Enums, Exceptions, Interfaces
   - Application: Interfaces, DTOs, Services, Validators
   - Infrastructure: Persistence, Repositories
   - Api: Controllers, Middlewares
   - Tests: UnitTests, IntegrationTests

6. Ignoring rules
   A .gitignore file tells git which files to ignore (build output, secrets,
   editor settings).

IMPORTANT CONFIRMATION
===================================

The project currently contains ZERO C# logic or implementation code.
There are no class files, no business rules, and no features written yet.
The .gitignore, the guide documentation, and the folder names are present,
but there is no real program logic so far. The next small steps are listed
as beginner-friendly tasks in the AVAILABLE_TASKS.md file.
